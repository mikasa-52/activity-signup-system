# 聚场 GatherHub · 在线活动报名管理系统

一个**纯前端**的活动报名管理系统产品原型，使用模拟数据与浏览器 `localStorage` 持久化，无需后端、数据库或构建工具，双击 `index.html` 即可运行。

> 所有数据均为演示用模拟数据，不包含任何真实个人信息。

---

## 一、功能页面

| 页面 | 路由 | 说明 |
| --- | --- | --- |
| 活动列表 | `#/list` | 活动卡片（渐变封面、时间、地点、报名进度、状态标签）、关键词搜索、状态筛选、空结果提示 |
| 活动详情 | `#/detail/:id` | 封面、完整信息、报名进度条、活动介绍、报名须知、报名入口（不可报名时禁用并说明原因） |
| 我的报名 | `#/my` | 电子报名凭证、按手机号筛选、查看活动详情、取消报名（二次确认） |
| 活动管理 | `#/admin` | 数据概览、活动表格、搜索、新建/编辑/删除活动、查看报名名单抽屉 |
| 新建 / 编辑活动 | `#/admin/new`、`#/admin/edit/:id` | 完整表单与字段级校验 |

### 核心业务流程

- **普通用户**：浏览活动 → 查看详情 → 填写姓名与手机号报名 → 获得报名编号 → 在「我的报名」查看凭证或取消
- **管理员**：查看活动列表 → 创建 / 编辑 / 删除活动 → 打开报名名单，搜索并按状态筛选报名记录

## 二、演示路径（建议按此顺序体验）

1. **浏览与搜索**：打开首页，在搜索框输入「厦门」，切换状态筛选（报名中 / 已满 / 未开始 / 已结束），观察空结果提示
2. **正常报名**：打开「2026 厦门前端工程化实战分享会」→ 立即报名 → 姓名填「测试用户」、手机号填 `13800138000` → 提交 → 记录报名编号
3. **重复报名校验**：返回详情页再次报名，用同一手机号提交，会提示「该手机号已报名本活动」
4. **格式校验**：手机号填 `12345`，字段下方会提示格式错误
5. **满员拦截**：打开「产品经理实战工作坊」（状态为「已满」），报名按钮被禁用并显示原因
6. **未开始拦截**：打开「社区公益市集」（状态为「未开始」），提示报名尚未开放及其开放时间
7. **已结束拦截**：打开「AI 应用开发闭门沙龙」（状态为「已结束」），报名入口关闭
8. **取消报名**：进入「我的报名」→ 找到刚提交的记录 → 取消报名 → 二次确认 → 名额释放（可回详情页确认人数下降）；「年度用户增长复盘会」的报名因活动已开始而不允许取消
9. **管理员创建活动**：切换到「管理员」→ 管理后台 → 新建活动 → 故意填「结束时间早于开始时间」或「人数上限为 0」，观察字段级报错 → 修正后保存，列表立即出现新活动
10. **管理员编辑**：编辑一个有报名的活动，把人数上限改到低于已报名人数，会被拦截
11. **查看名单**：在管理后台点击「名单」，抽屉中搜索姓名 / 手机号 / 报名编号，切换「仅已报名 / 全部记录」
12. **重置数据**：页脚「重置演示数据」，二次确认后恢复初始状态

## 三、模拟数据说明

- 首次打开时自动生成 **6 场活动**，覆盖全部状态：报名中 ×2、已满 ×1、进行中 ×1、未开始 ×1、已结束 ×1
- 每场活动包含 0–60 条报名记录（姓名与手机号均为构造数据，如 `13800138001`）
- **活动时间以「首次打开的时间」为基准按天偏移生成**，因此无论何时打开，各状态都能正确复现；状态本身由当前时间与报名人数**实时计算**，不写死
- 数据保存在 `localStorage`，键名为 `gatherhub.demo.v1`；清除该键或点击页脚「重置演示数据」即可恢复初始状态

### 状态判定规则

| 状态 | 判定条件 | 能否报名 |
| --- | --- | --- |
| 已结束 | 当前时间 ≥ 活动结束时间 | 否 |
| 进行中 | 活动开始时间 ≤ 当前时间 < 结束时间 | 否 |
| 未开始 | 当前时间 < 报名开放时间 | 否 |
| 已满 | 已报名人数 ≥ 人数上限 | 否 |
| 报名中 | 其余情况 | 是 |

取消报名限制：**活动开始后或已结束时不可取消**，取消后立即释放名额。

## 四、本地打开方式

**方式一（最简单）**：直接双击 `index.html`，用浏览器打开即可。

**方式二（推荐，行为与线上一致）**：在本目录启动一个静态服务器：

```bash
# Python 3
python -m http.server 8765

# 或 Node.js
npx serve .
```

然后访问 <http://127.0.0.1:8765/index.html>。

> 说明：`file://` 协议下部分浏览器会限制 `localStorage`，此时刷新页面数据会重置，改用方式二可正常持久化。

## 五、技术说明

- **纯静态**：`index.html` + `styles.css` + `app.js`，零依赖、零构建、可离线运行
- **无外链资源**：封面由 CSS 渐变 + 内联 SVG 图标实现，字体使用系统字体栈，不请求任何 CDN
- **路由**：基于 `location.hash` 的轻量路由（`#/list`、`#/detail/:id`、`#/my`、`#/admin`）
- **资源路径**：全部使用相对路径，无 `/` 开头的绝对路径，可直接部署到 GitHub Pages 子路径
- **响应式**：≤820px 折叠导航、卡片单列、表格横向滚动，触控目标不小于 40px
- **可访问性**：表单 `label` 关联、`aria-invalid` / `aria-describedby` 错误提示、`role="dialog"` + `aria-modal`、`aria-live` toast

### 部署方式一：网页手动配置（最省事）

1. 在本目录执行 `git remote add origin https://github.com/<用户名>/activity-signup-system.git` 并 `git push -u origin main`
2. 进入仓库 `Settings → Pages`
3. Source 选择 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`
4. 保存后等待约 1 分钟，访问 `https://<用户名>.github.io/activity-signup-system/`

### 部署方式二：API 脚本（`github.com` 被墙时可用）

当前网络环境下 `github.com` 不可达，但 `api.github.com` 与 `*.github.io` 均可访问，
因此提供 `deploy.mjs`，通过 GitHub REST API 完成建仓 → 上传 → 开启 Pages 全流程，无需 `git push`：

```bash
set GITHUB_TOKEN=ghp_xxxx          # Windows CMD
node deploy.mjs
```

- 需要 Token 具备：`Administration`（建仓）、`Contents`（写文件）、`Pages`（开启托管）读写权限
- 脚本会在仓库名被占用时自动追加 4 位随机后缀
- 部署结束后自动轮询构建状态并请求一次预览地址，输出 HTTP 状态码

## 八、已知边界

- 无真实登录体系，「我的报名」展示当前浏览器 `localStorage` 中的全部报名记录，通过手机号筛选定位本人记录
- 角色切换仅用于演示视角差异，不做权限校验
- 报名编号为本地生成，不含校验位，仅用于演示核验流程
